# Hub-Mind — System Audit & Upgrade Plan (Phases 1–10)

This branch is intentionally isolated from `main`. The goal is to make Hub-Mind behave like a live business workspace rather than a demo/prototype, with Firebase as the online source of truth and browser storage used only for genuine offline continuity.

## Phase 1 — Data integrity and source-of-truth

- Firestore is authoritative whenever the device is online.
- Empty Firestore snapshots must never be treated as permission failures and must never resurrect browser-cached records.
- Legacy demo/seed records must not be generated by the application.
- Legacy demo IDs are filtered from document display and old local caches are cleaned.
- Deleted documents must be removed from the local cache and protected by tombstones so background saves cannot resurrect them.
- Document autosave must never overwrite a loaded document with a blank editor state.

## Phase 2 — Firebase CRUD correctness

- Create/update/delete operations must report failures instead of silently pretending the UI operation succeeded.
- Permanent document deletion must be server-confirmed before the UI treats the operation as complete.
- Offline queues must not sync records that have been tombstoned/deleted.
- Live listeners must remain subscribed after empty collections and must reflect additions/deletions immediately.

## Phase 3 — Documents/editor

- Document ordering uses latest edit/save time.
- Editor content and content JSON remain compatible with recovery/version history.
- Blank-state protection remains in place during initial Firestore loading.
- Templates remain real documents and must save through the same persistence path as blank documents.
- The editor must never use a stale browser copy as an authoritative online replacement.

## Phase 4 — Tasks, meetings and recurring schedules

- Recurring meeting templates are persisted in `recurringMeetingTemplates`.
- Materialized meeting IDs are deterministic, making generation idempotent.
- Recurring task processing is separate from ordinary task CRUD.
- Existing occurrences remain intact when a recurrence template is stopped.
- Workspace permissions are enforced in Firestore rules rather than relying only on client filtering.

## Phase 5 — Clients, projects and follow-ups

- Live Firebase listeners are used for workspace records.
- Local storage is continuity-only while genuinely offline.
- Empty online collections must display as empty rather than showing stale/demo records.

## Phase 6 — Sharing and direct links

- Shareable records should resolve to the exact document/task/event, not merely the parent tab.
- Shared views must be read-oriented and respect authentication/authorization.
- WhatsApp sharing should use human-readable line breaks rather than literal `\\n` sequences.

## Phase 7 — Shawn AI

- Shawn remains a live-chat assistant rather than a wake-word microphone service.
- AI actions must be authenticated and scoped to the workspace.
- Document questions should continue to use the live document context/Gemini integration.
- Destructive actions require explicit confirmation.

## Phase 8 — PWA/mobile reliability

- Service-worker updates must not trap users on stale application bundles.
- iOS/Safari should receive a deterministic update/reload path.
- Manifest icons must be valid and present at their referenced paths.
- Mobile editor controls must remain usable without requiring repeated taps.

## Phase 9 — UI/UX resilience

- Lists should expand naturally on small screens rather than trapping content inside unnecessarily short panels.
- Documents/tasks should use clean rows/cards with the primary action obvious.
- Editor canvas should preserve document-like proportions while allowing touch zoom.
- Loading, empty, error and saved states must be visually distinct.

## Phase 10 — Regression gate

Before this branch is considered ready for `main`:

1. TypeScript validation passes.
2. Production Vite build passes.
3. Firebase rules cover every live collection used by the application.
4. No code path intentionally seeds demo business records.
5. Online empty Firestore collections do not fall back to local cache.
6. Document deletion cannot be undone by autosave/sync.
7. Document loading cannot be overwritten by a blank editor state.
8. Recurring events can be created, materialized, displayed, and stopped.
9. Existing data remains visible from Firebase after refresh.
10. The branch is tested as a whole before any merge to `main`.

## Current branch policy

`audit-phase-1-10` is the working branch. No merge to `main` is authorized by this audit. All changes should be committed here until the full regression gate passes.
